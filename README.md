# Screens N Blinds

A complete Next.js App Router website built from `DESIGN_BLUEPRINT.md` and `WEBSITE_CONTENT.md`. Bright, minimal commercial design (white and warm-grey surfaces, slate text and buttons, a single apricot accent) with Manrope / DM Sans typography: a USP top bar, sticky centred-logo header with hover mega-menus, full-bleed and circular heroes, arched-top category cards, edge-to-edge split features with tick-mark checklists, centred section introductions with italic accent words, GSAP scroll reveals, architectural illustration placeholders, responsive navigation, seven blind and five curtain detail pages, inspiration gallery, a USP footer and a server-validated enquiry integration.

## Run locally

Use Node.js 20.9 or newer (developed with Node 24) and npm.

```sh
npm ci
cp .env.example .env.local
npm run dev
```

Open http://localhost:3000. On Windows PowerShell, use `npm.cmd` / `npx.cmd` if script execution policy blocks `npm.ps1`. Use `Copy-Item .env.example .env.local` instead of `cp` if preferred.

```sh
npm run lint
npx tsc --noEmit
npm test
npm run build
npm start
```

The fonts use `next/font/google`: the build needs access to Google Fonts and packages need access to the npm registry. Fonts are self-hosted by Next.js after build. No remote image hosts are needed.

## Replace images

See [IMAGE_GUIDE.md](./IMAGE_GUIDE.md) for the complete filename checklist across all six categories. Every detail page includes three individually replaceable gallery images. Run `npm run images` after dropping in photographs to refresh the asset manifest without restarting development.

No supplied photography was available. The three original SVG architectural studies explicitly illustrate roller, Roman and Venetian blinds. They are placeholders, not stocked products, photography, or completed client work. No reference-site imagery was copied. These assets are generated by `scripts/create-placeholders.mjs` and require no third-party stock licence.

1. Put approved WebP images into the corresponding folders in `public/images/`.
2. Use the filenames in `content/images.ts` and `content/gallery.ts`, or edit those central paths.
3. Update `alt`, `position`, `mobilePosition`, source, licence and actual-project metadata to accurately describe the replacement.
4. Restart `npm run dev` or rebuild. `scripts/image-manifest.mjs` runs automatically and records existing local files in `content/image-manifest.json`.

The reusable `ImagePlaceholder` component uses the manifest to select an existing image or an original illustration; it never requests nonexistent image URLs. Real raster assets use `next/image` optimisation with responsive sizes. Development mode shows a small requested-filename label. Illustrative gallery wording should be updated when approved photographs replace the studies.

Use a wide hero crop (roughly 2000px wide) and portrait-friendly category compositions. Verify each blind is identifiable. Keep imagery compressed and provide correct source/permission records. Use `mobilePosition` for an appropriate mobile focal point.

## Configure enquiry delivery

Without delivery configuration, the UI explicitly says online enquiries are unavailable, disables submission, and the API returns 503. It never reports fake success. Query strings such as `/contact?product=roman-blinds` select the appropriate product.

Set the following **server-only** environment variables:

```text
RESEND_API_KEY=your_provider_key
ENQUIRY_FROM=verified_sender_address
ENQUIRY_TO=approved_receiving_address
UPSTASH_REDIS_REST_URL=your_redis_rest_url
UPSTASH_REDIS_REST_TOKEN=your_redis_rest_token
```

Verify a sending domain with Resend, then use a sender on that domain. The API sends plain text and sets the customer as `reply_to`, never as the sender. A real provider response with a message ID is required before success is shown; provider acceptance does not guarantee inbox delivery. Before launch, submit a real enquiry and confirm it arrives.

Production delivery requires durable Redis rate limiting. A single atomic Redis command limits each client IP to five attempts per ten minutes. Development alone may use an in-process limiter. Vercel supplies the trusted forwarding header; review trusted-proxy handling if hosting elsewhere. Rate-limiter failures fail closed. Validation, a honeypot, same-origin checking, payload limits and provider timeouts are also implemented. No enquiry content is logged or stored by the application; Resend and Redis have their own data handling policies. Review privacy text and provider retention with the business owner.

No privacy-policy page is published because accurate legal/business details have not been supplied. Add an approved policy and link it from the form and footer before launch.

## SEO and deployment on Vercel

1. Push this folder to a Git repository and import it into Vercel as a Next.js project.
2. Add the server environment variables above and set `NEXT_PUBLIC_SITE_URL` to the approved HTTPS origin.
3. Run the production build and deploy. Use the Node.js runtime for the enquiry endpoint; do not configure static export.
4. Test delivery, desktop/mobile layouts, domain redirects and the approved privacy policy on the actual deployment.

Until a public origin is configured, pages are `noindex`, robots disallows crawling, the sitemap is empty, and no fictional canonical URL is emitted. Once set, unique page metadata, canonical links, the sitemap and robots use the approved domain. An original typographic Open Graph image is generated by `app/opengraph-image.tsx`.

This handover is a local Next.js/Vercel project; no hosted site has been published.

## Browser checks

Motion uses GSAP with route-scoped cleanup. `CursorFeedback` adds small button responses on fine-pointer devices, with no custom cursor overlay. Responses are disabled for forms, dialogs, keyboard navigation, touch and reduced motion. `app/motion.css` controls the appearance. Scroll effects include staggered movement, image masks, selected desktop parallax, divider reveals and a reading-progress line. No scrolling is hijacked and supporting text stays fully opaque.

With a production server running on port 3000:

```sh
npx playwright test
```

The configuration uses installed Microsoft Edge. On another machine change `channel` in `playwright.config.ts` or install Playwright Chromium and remove the channel override. Screenshots are written to `test-results/` (ignored). Tests cover all routes, image loading, internal links, errors, unknown products, widths 360/390/430/768/1024/1280/1440/1920, modal focus/scroll lock, gallery controls, and product preselection. Unit/API tests verify validation and truthful unconfigured responses. Provider delivery still requires an end-to-end test with actual credentials.
